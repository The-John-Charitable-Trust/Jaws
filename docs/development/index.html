B2.1 — Deployment proposal implementation; live installation pending

Stage B: Supervisor Agent

Implement Foundry-hosted Supervisor with structured delegation to specialist workers, correlation IDs, typed outputs and failure handling.

First tangible installation target: a Foundry hosted Supervisor agent running a Linux/amd64 container that serves Responses protocol v2.0.0. Existing Foundry, project and model are reused. Foundry currently requires a compatible hosted-agent package or container plus deployment permissions; the model alone does not constitute a hosted agent.

Installer proposal: with an Azure-aware read-only plan and an approved digest-pinned Azure Container Registry image, add -SupervisorImage to produce an immutable-input SHA-256 proposal fingerprint in installer/.local/. This fingerprints the request only; it is not proof of entitlement, human approval, cost verification, or deployment. The installer does not yet enable -Mode Install.

.\installer\Install-Jaws.ps1 -Mode Plan -AzureAware -PlanFile .\installer\.local\jaws-plan.dev.json -StateFile .\installer\config\jaws-installation-state.dev.json -SupervisorImage "registry.azurecr.io/jaws/supervisor@sha256:<64-digit-sha256>" -NonInteractive

B2.1 runtime and packaging implementation (awaiting build and independent QA): The dedicated src/Jaws.Supervisor.Host .NET 10 web project uses Microsoft Agent Framework Foundry hosting and publishes the /responses endpoint; a multi-stage Dockerfile describes a Linux port-8088 image. The installer now accepts -Mode Package and optionally -BuildContainer to compile locally only. It does not connect to Azure, push images to ACR, register a hosted agent or perform inference.

.\installer\Install-Jaws.ps1 -Mode Package
# Optional, after Docker Desktop is installed and running:
.\installer\Install-Jaws.ps1 -Mode Package -BuildContainer
Import-Module Pester -RequiredVersion 5.9.1 -Force
Invoke-Pester .\tests\installer\ -Output Detailed

Expected build output is under installer/.local/supervisor/publish and the optional local Docker tag is jaws-supervisor:local. Five added structural/safety tests bring the expected test count from 45 to 50, subject to independent execution. A successful local build is not proof of deployability or a cloud installation. Package restore and Docker base-image downloads may require internet access.

Container registry readiness checkpoint (implementation pending independent testing): With an existing, authorized Azure Container Registry, the installer now supports -Mode Plan -AzureAware -RegistryName <existing-registry-name> to read registry identity and configuration and generate installer/.local/jaws-acr-readiness.dev.generated.json. It performs zero Azure writes and refuses publication; absent registries block rather than being provisioned automatically. Six additional offline Pester tests raise the expected suite from 51 to 57. See Supervisor installation checkpoint.

Dedicated registry selected: The dedicated JAWS Basic Azure Container Registry now has an installer-only Plan/Create path in installer/Install-JawsRegistry.ps1. Run Plan first with an available lowercase globally unique registry name, review its exact scope, configuration and recurring-cost warning, then run Create only with the matching PlanSha256 and -AcknowledgeBillableBasicSku after obtaining financial approval. The registry remains uncreated until that explicitly authorized Create run succeeds. No direct Azure provisioning commands are required; eight new offline tests have been added. See detailed registry installation procedure.

Prerequisite before first deployment: produce a tested JAWS Supervisor Responses-compatible container (Linux/amd64), push it through installer-mediated automation into an approved ACR, verify Foundry Project Manager and image-reader permissions, and approve estimated charges. The new proposal tests validate no cloud writes. No deployment should be attempted merely because an image digest or hash is present.
