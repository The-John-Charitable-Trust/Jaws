Introduction

JAWS Platform Overview

JAWS is an agentic platform for virtual-machine security incidents. The operator talks to the hosted Supervisor in Teams. The Supervisor delegates to one specialist at a time. The virtual-machine specialist investigates, deliberates, and remediates in the compute environment it owns, using Azure MCP. The observability specialist uses that same environment through a custom MCP server. Datadog, Azure Monitor, Azure Sentinel, and ServiceNow incident records are tools on that server. Both specialists stay within the operator's RBAC role. One project has many conversations. The code contract is SpecialistCatalog.

Operational Reference Architecture

Concept of Operations

An operator starts a Teams conversation under a project. The Supervisor delegates the virtual-machine security incident to the virtual-machine specialist and observability work to the observability specialist. Azure MCP runs in the specialist's compute environment. The observability custom MCP server runs there too. Every action is checked against the RBAC role of that operator.

Primary use case

Investigate an Azure operational incident: collect Policy, Defender and observability evidence; identify likely causes; compare remediation options; present cited findings and what-if impact; request explicit approval before any authorized execution; retain traceable evidence of actions and outcomes.

Agent communication and evidence contract

Every delegated task should carry correlation and session identity, least-privilege authorization, explicit scope and timeout, structured outputs and source citations. The Supervisor must not represent unconnected tools as available or claim remediation occurred without verifiable execution evidence.

STEP D · Planned

Step D: Virtual-machine specialist and compute

Stand up the one virtual-machine specialist that will investigate, deliberate, and remediate virtual-machine security incidents, and the one compute environment it owns. The Supervisor delegates the incident to this specialist. No second sandbox is created.

Planned. Acceptance is a delegated incident task running on this specialist and its compute environment. Azure MCP, remediation, observability, and Teams are later steps.

STEP E · Planned

Step E: Azure MCP investigation

The same virtual-machine specialist investigates through the Azure MCP server inside its compute environment and returns cited evidence. A request outside the operator's RBAC role is denied.

Planned. No implementation or validation claim is made for this step.

STEP F · Planned

Step F: Deliberation and remediation

The same virtual-machine specialist deliberates and performs development, configuration, or remediation in its compute environment. The action is denied when the operator's RBAC role does not allow it. There is no separate deliberation or remediation agent.

Planned. No implementation or validation claim is made for this step.

STEP G · Planned

Step G: Observability specialist

One observability specialist uses the virtual-machine compute environment through a custom MCP server. Its tools are Datadog, Azure Monitor, Azure Sentinel, and ServiceNow incident records. The Supervisor delegates observability work to it. It does not receive its own sandbox and cannot exceed the operator's RBAC role.

Planned. No implementation or validation claim is made for this step.

STEP H · Planned

Step H: Teams projects and conversations

The operator converses with the Supervisor in Teams. Each conversation belongs to one project, and one project has many conversations. The operator's RBAC role is the role both agents are checked against.

Planned. No implementation or validation claim is made for this step.

STEP I · Planned

Step I: End-to-end acceptance

One Teams conversation produces a virtual-machine security incident result: the virtual-machine specialist investigates, deliberates, and remediates; the observability specialist uses the same compute environment; both stay within the operator's role; the conversation stays under its project.

Planned. No implementation or validation claim is made for this step.
