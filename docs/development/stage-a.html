Detailed engineering tutorial with configuration JSON, actual PowerShell implementation, copyable commands, language tabs, expected evidence and testing.

Status: Stage A discovery accepted. This tutorial follows the current JAWS implementation. All Azure queries are read-only.

1. What Stage A builds

Stage A establishes a state-first, read-only Azure discovery and reconciliation pipeline. The installer treats an operator-maintained JSON manifest as desired state and checks live Azure resources without changing them.

4. Study the actual PowerShell state parser

The code below is from installer/modules/InstallationState.psm1. It validates the supported schema version, required fields, subscription GUID, resource types and duplicate entries. StrictMode makes missing/incorrect assumptions visible.

PowerShellActual source: Read-JawsInstallationState
function Read-JawsInstallationState {
    [CmdletBinding()]
    param([Parameter(Mandatory)][string]$Path)
    if (-not (Test-Path -LiteralPath $Path)) { return $null }
    $state=Get-Content -LiteralPath $Path -Raw | ConvertFrom-Json -ErrorAction Stop
    if ($state.SchemaVersion -notin @('1.1') -or $state.Platform -ne 'JAWS' -or $null -eq $state.Resources) {
        throw 'JAWS-STATE-001: Unsupported or malformed JAWS installation state (expected 1.1).'
    }
    $subscriptionGuid=[guid]::Empty
    if (-not [guid]::TryParse([string]$state.SubscriptionId,[ref]$subscriptionGuid)) {
        throw 'JAWS-STATE-001: Installation state contains an invalid Azure subscription ID.'
    }
    if (-not [string]$state.ResourceGroupName -or -not [string]$state.EnvironmentName) {
        throw 'JAWS-STATE-001: Installation state must identify its environment and resource group.'
    }
    $supported=@('Microsoft.CognitiveServices/accounts','Microsoft.CognitiveServices/accounts/projects',
        'Microsoft.CognitiveServices/accounts/deployments','Microsoft.KeyVault/vaults')
    $keys=@{}
    foreach($r in @($state.Resources)) {
        if (-not $r.Name -or $r.Type -notin $supported -or [string]$r.Name -match '(?i)tight.?fang|tfang') {
            throw 'JAWS-STATE-004: Invalid or non-JAWS resource in installation state.'
        }
        $key=([string]$r.Type + '|' + [string]$r.Name).ToLowerInvariant()
        if ($keys.ContainsKey($key)) { throw "JAWS-STATE-005: Duplicate state resource $key" }
        $keys[$key]=$true
    }
    return $state
}

Read and understand each guard before changing the state format. Validation errors block the installer; they are not permission to fabricate replacement resource identities.

6. Understand the reconciliation algorithm

Discovery gathers actual state; reconciliation decides whether it matches the desired-state inventory. This is the existing tenant scan comparison function, not pseudocode.

PowerShellActual source: Compare-JawsTenantScanToState
function Compare-JawsTenantScanToState {
    [CmdletBinding()]
    param([Parameter(Mandatory)]$State,[Parameter(Mandatory)]$Scan)
    $comparisons=@()
    foreach($r in @($State.Resources)) {
        $matching=@($Scan.Candidates | Where-Object {
            $_.Platform -eq 'JAWS' -and $_.SubscriptionId -ieq $State.SubscriptionId -and
            $_.ResourceGroup -ieq $State.ResourceGroupName -and $_.Type -ieq $r.Type -and
            ($_.Name -ieq $r.Name -or $_.Name -like "*/$($r.Name)")
        })
        # Tenant heuristics may miss resources without a JAWS name/tag.
        # A missing match is NOT proof of absence; targeted discovery follows.
        $classification=if ($matching.Count -eq 1) { 'CandidateLocated' } elseif ($matching.Count -gt 1) {'Ambiguous'} else {'NotInTenantCandidateScan'}
        $observedId=if ($matching.Count -eq 1) { [string]$matching[0].ResourceId } else { $null }
        $idMatch=if ($r.ResourceId -and $observedId) { $r.ResourceId -ieq $observedId } else { $null }
        if ($idMatch -eq $false) { $classification='IdentityDrift' }
        $comparisons += [pscustomobject]@{Name=$r.Name;Type=$r.Type;Status=$classification;ExpectedResourceId=$r.ResourceId;ObservedResourceId=$observedId}
    }
    return @($comparisons)
}

Missing target resources and incomplete scans are failures. Related Tight Fang resources do not become JAWS resources merely because they share a subscription.

9. Troubleshooting and least-privilege safeguards

Check subscription permissions and the gold-copy manifest before rerunning a failed discovery. Do not change protected infrastructure, ignore a mismatch, or force-sync Git.

PowerShellRead-only diagnostics
git status -sb
az account show --query "{subscription:id,tenant:tenantId,user:user.name}" -o json
Get-Content ".\installer\config\jaws-installation-state.dev.json" -Raw | ConvertFrom-Json | Select-Object SubscriptionId,ResourceGroupName,EnvironmentName
Stage A Discover must remain read-only. A remediation, new resource, role assignment or subscription switch is a separate Stage B planning/approval task.
