# JAWS installation implementation roadmap

**Baseline:** 15 October 2026. **Authority:** Microsoft Learn / Microsoft technical documentation for product capabilities and best practices; checked-in code and acceptance receipts for actual JAWS implementation state.

This is the **installation and architecture track (Steps A onward)**, not the separate legacy [Agent Framework tutorial track](../agent-framework-track.md) (Steps 1–10). Steps A and C are accepted for the dev project. Step B and Step D have installers. A fresh-subscription receipt is not recorded for either, so neither is accepted. Steps E–I are not implemented.

## Approved end state

An operator converses with the Supervisor in Microsoft Teams. The Supervisor is the proxy to the specialist agents. It does not call Azure or observability products itself. The planned routing contract is a versioned JSON catalog that the Supervisor loads from the project. `RoleAgentCatalog` in `src/Jaws.AgentFramework/Agents/RoleAgentCatalog.cs` is the older tutorial scaffold (Support, Governance, Deploy, Workflow). It is not this catalog, and `SpecialistCatalog.cs` is not in the repository.

- One specialist is one agent. That agent investigates, deliberates, and remediates its own job. Investigation, deliberation, and remediation are not separate agents.
- A tool is one callable action. A skill is a versioned procedure the specialist loads when the task matches. A skill does not create an agent. Investigation and deliberation are skills. An approved change is a workflow: it checks identity, the operator's RBAC, and a human approval, then calls one write tool. Acceptance does not depend on the Foundry Skills API preview. The same `SKILL.md` files ship with the specialist.
- The virtual-machine specialist owns one compute environment for development, configuration, and remediation. It is a hosted agent. Hosted `jaws-investigation-dev` is the starting point for this specialist. The Step C prompt planner remains the planning callee and is not this specialist. The virtual-machine specialist's Azure MCP allow-list is the tools for one virtual-machine security incident: the machine and its identity, its network attachments, Azure Policy and Microsoft Defender evidence, and the metrics and logs for that machine. It does not receive the entire Azure MCP catalog. Investigation runs read-only.
- The observability specialist is a prompt agent. It uses that same compute environment through one custom MCP server. JAWS does not add a second sandbox or a separate Datadog specialist. The Datadog Agent program runs on one default virtual machine in that same environment and sends that machine's telemetry to Datadog. The machine must already exist in the install subscription, the environment resource group (`-ResourceGroupName`; `rg-aiops-lab-test2` for the current test, or `rg-jaws-<environment>` when the generated name is kept), and the environment location (`-Location`; `eastus` for the current test). `jaws-stepb-test` in `rg-jaws-stepb-test` is the operator machine and is not that host. The Datadog Agent must be installed, configured, and running on the host before Datadog is configured. When the observability specialist is built, its skills and tools are compiled modules added to this one custom MCP server. The metadata those modules use is the install-time ServiceNow and Datadog input. The server is stateless and scales by adding replicas. Each product action is a compiled module named by a JSON manifest. The manifest selects a module and a secret name. It cannot add an arbitrary URL or a script. Enabling a tool on the server does not grant it to every agent. The specialist's `allowedTools` list is the grant. The first modules are Datadog, Azure Monitor, Azure Sentinel, and ServiceNow incident records. ServiceNow login URL, username, and password, and the Datadog site, API key, application key, and default virtual machine resource id, are Key Vault secrets named in [STEP-G-OBSERVABILITY.md](STEP-G-OBSERVABILITY.md). Step B Install asks whether to configure ServiceNow and whether to configure Datadog. Skip leaves that product unset. Skipping Datadog requires no Datadog Agent host. A yes answer, `-InstallConfig`, or matching command parameters supply the values, and Install writes them into the Step B vault. The generated file `installer/.local/jaws-install.<environment>.generated.json` records the secret names and a FedRAMP Moderate row for every Azure resource the install creates or depends on. Secret values stay out of that file. `Set-JawsObservabilityIntegration.ps1` writes the same secrets later. Neither command installs the Datadog Agent or Step G.
- A later specialist, including Azure network, Azure storage, and ServiceNow change or request fulfillment, is another catalog entry. Those specialists are not gates in Steps D–I. A prompt specialist does not need a new container. Loading a valid catalog entry does not require a new Supervisor image.
- Every specialist acts only within the RBAC role of the operator who started the Teams conversation. A missing role denies the call. It is not a prompt to grant a broader role.
- Teams conversations are categorized by project. One project has many conversations, and each conversation belongs to one project. The conversation stores that thread, including tool calls and approvals. The project record stores the durable shared facts: incident, machine, decisions, approvals, and evidence citations. A new conversation in the same project starts from that record. A conversation from another project is not returned. Foundry long-term memory is preview and is reserved for one operator's preferences. It is not the incident record, and acceptance does not depend on it.

## Network boundary

Recorded 20 October 2026. Specialists stay inside the customer virtual network. The Supervisor reaches them through Foundry tool calls on that network. A public specialist URL is outside this operating model.

Foundry-to-Foundry A2A uses `https://<account>.services.ai.azure.com/api/projects/<project>/agents/<agent>/endpoint/protocols/a2a` for the dev project and for every customer environment. The connection is `AgenticIdentityToken`, audience `https://ai.azure.com`. The installer does not set an agent-card path and does not set `send_credentials_for_agent_card`. A connection left on `cognitiveservices.azure.com` is moved back to the `services.ai.azure.com` project route by Step C Install. The dev project already uses that route and stays there.

Microsoft documents three egress choices, and the choice is made when the Foundry account is created. Injection cannot be added later. The supported private choice is bring-your-own virtual network: a subnet delegated to `Microsoft.App/environments`, a private endpoint, private DNS, and public network access disabled. A2A, MCP, and OpenAPI tools are supported through that subnet. Foundry's built-in browser automation is not supported under network isolation. JAWS browser control is the internal OpenAPI Container App, which is the supported private path.

An account that has agent injection and public network access left enabled is not one of those three choices. On the recreated `aiops-lab-test2` account, the `services.ai.azure.com` protocol routes did not map, and the public `cognitiveservices.azure.com` A2A path returned 401 to the agent identity. That resource group has been deleted. The next functional test creates a new public-egress account with no `networkInjections`, the same shape as the dev account, and leaves the A2A target on `services.ai.azure.com`. Do not run `Install-JawsFoundryPrivateNetwork.ps1` before Step C prints `TOOL_INVOKED_SUCCEEDED` and `TASK_STATE_COMPLETED`. That command deletes the account and recreates it with injection while public network access stays enabled.

The virtual-machine specialist and the observability specialist are reached as MCP or OpenAPI from the delegated subnet. The virtual-machine round trip uses the Foundry responses path. It does not use A2A `SendMessage` against the hosted virtual-machine specialist. The operator machine that calls a private-only account is in that virtual network or peered to it. `jaws-stepb-test` on `jaws-stepb-testVNET` can operate the public-egress test. It cannot operate a private-only account until it joins or peers to the Foundry virtual network.

Sources: [Foundry networking options](https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/networking-options), [private networking](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/virtual-networks), [Foundry-to-Foundry A2A](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/tools/agent-to-agent), [private link](https://learn.microsoft.com/en-us/azure/foundry/how-to/configure-private-link), [toolbox network isolation](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/tools/toolbox-network-isolation).

## FedRAMP Moderate acceptance

FedRAMP Moderate is a customer configuration gate on the resources each step creates. It is separate from the functional line the installer prints. A functional pass on a public-egress account leaves `Customer installation accepted` false and leaves the FedRAMP gate open. These criteria describe the configuration a customer aligns with the named control families. They are not a FedRAMP authorization of JAWS, and they are not Azure's platform authorization.

## Extension contract

Recorded 18 October 2026. Step D writes `installer/.local/jaws-specialist-catalog.<environment>.generated.json` and can create one hosted virtual-machine specialist. Outside the dev project it also provisions a private browser for the Supervisor and that specialist. The Investigation prompt planner does not receive it. Install does not rebuild the Supervisor image. `Publish-JawsSupervisorBrowserImage.ps1`, `Test-JawsBrowserPrivatePath.ps1`, and `Test-JawsBrowserCapability.ps1` are separate acknowledged commands. A capability PASS is not a fresh-subscription receipt. The custom MCP server, skill files, and Steps E–I are not implemented.

A specialist entry names the Foundry agent, `prompt` or `hosted`, the model, instructions, skill names, one MCP server, an allow-list of tool names, and whether writes require approval:

```json
{
  "id": "observability",
  "foundryAgentName": "jaws-observability",
  "kind": "prompt",
  "skills": ["correlate-incident-signals"],
  "mcpServer": "jaws-observability",
  "allowedTools": ["datadog.metrics.query", "monitor.metrics.query", "sentinel.incidents.query", "servicenow.incident.update"],
  "writesRequireApproval": true
}
```

A custom MCP manifest entry names a tool, the compiled module that implements it, whether it is read-only, and the secret it may use:

```json
{
  "name": "datadog.metrics.query",
  "module": "Datadog",
  "readOnly": true,
  "secret": "jaws-datadog-api-key"
}
```

The Supervisor refuses a catalog that names an unknown tool, splits one job into phase agents, or grants a write without the approval workflow. The MCP server refuses a manifest entry whose module is not in the build.

## Step C final architecture and evidence

`jaws-supervisor-dev` v5 -> `jaws-investigation-a2a-dev` (`AgenticIdentityToken`, RemoteA2A) -> toolbox `jaws-investigation-a2a-tools` v2 -> `jaws-investigation-planner-dev` prompt agent v1. The standalone hosted `jaws-investigation-dev` v1 remains in place but **did not execute** the Step C A2A task. Hosted-agent A2A `SendMessage` returned `HOSTED_AGENT_NOT_SUPPORTED`; this is why the approved A2A callee is the prompt planner.

Acceptance, as reported in the Step C closure: Supervisor v5 immutable image `sha256:86c556fff7f54eb8ad81c84bc768093fd7bc083e941e9e16bbf1ea8bc0cfa289`; response `caresp_0ca3823766edf3dc00biTZLQVBWJSTvfc8sy4PrBBEV9zGJyvB`; A2A task `TASK_STATE_COMPLETED`. The operator check for that project is `installer/Install-JawsThroughStepC.ps1 -Mode Validate`. The functional test of the delegation is the same command with `-AcknowledgeInferenceCharges` (model usage, no Azure configuration writes). `-Mode Install -AcknowledgeStepCInstall` repairs one known gap per gate and is not required when Validate is already clean. [Closure commit](https://github.com/The-John-Charitable-Trust/Jaws/commit/401c7af751906a47c6d42cd0ffc1f473ad37f320); [merged PR #1](https://github.com/The-John-Charitable-Trust/Jaws/pull/1); runbook: [STEP-C-RUNBOOK.md](STEP-C-RUNBOOK.md).

The same entry point accepts `-EnvironmentName` and reads the Step B receipt for that environment. It configures `jaws-investigation-planner-<environment>` and RemoteA2A connection `jaws-investigation-a2a-<environment>`. The customer target is the same `services.ai.azure.com` planner route the dev project uses. It does not call the dev project. Offline Pester covers that path with a CLI stand-in. A fresh-subscription `TASK_STATE_COMPLETED` receipt has not been recorded, so that path is not accepted. A functional pass on the public-egress restart does not meet the FedRAMP Moderate criterion and leaves `Customer installation accepted` false.

**Do not** interpret Step C closure, or a Step D stub pass, as proof of the end state. Step D can record the catalog, one hosted specialist, and, outside the dev project, a private browser toolbox, a later Supervisor image, a private-path session open, and a capability check. A stub pass does not prove a live page load, a vault login, or a tenant signature check. Azure MCP, deliberation, remediation, the observability specialist, and Teams are Steps E–I and are not installable.
