# JAWS installation implementation roadmap

**Baseline:** 15 October 2026. **Authority:** Microsoft Learn / Microsoft technical documentation for product capabilities and best practices; checked-in code and acceptance receipts for actual JAWS implementation state.

This is the **installation and architecture track (Steps A onward)**, not the separate legacy [Agent Framework tutorial track](../agent-framework-track.md) (Steps 1–10). Steps A–C are accepted for the dev project. Steps D–I are the remaining sequence to the end state below. They are not implemented.

## Approved end state

An operator converses with the Supervisor in Microsoft Teams. The Supervisor delegates a virtual-machine security incident to two specialists and does not call Azure or Datadog itself.

- One worker agent investigates, deliberates, and remediates that incident. It owns one compute environment used for development, configuration, and remediation. Its tools are the Azure MCP server.
- One Datadog agent uses that same compute environment through a custom Datadog MCP server. It does not receive a second sandbox.
- Both agents act only within the RBAC role of the operator who started the Teams conversation. An agent identity must not exceed that role.
- Teams conversations are categorized by project. One project has many conversations, and each conversation belongs to one project.

The Step C prompt planner is the accepted planning callee. It is not this worker. Hosted `jaws-investigation-dev` is the starting point for the worker, not a third specialist. A separate deliberation agent, a separate remediation agent, a second compute environment, ServiceNow, and a document-retrieval product are not part of this end state.

## Step C final architecture and evidence

`jaws-supervisor-dev` v5 -> `jaws-investigation-a2a-dev` (`AgenticIdentityToken`, RemoteA2A) -> toolbox `jaws-investigation-a2a-tools` v2 -> `jaws-investigation-planner-dev` prompt agent v1. The standalone hosted `jaws-investigation-dev` v1 remains in place but **did not execute** the Step C A2A task. Hosted-agent A2A `SendMessage` returned `HOSTED_AGENT_NOT_SUPPORTED`; this is why the approved A2A callee is the prompt planner.

Acceptance, as reported in the Step C closure: Supervisor v5 immutable image `sha256:86c556fff7f54eb8ad81c84bc768093fd7bc083e941e9e16bbf1ea8bc0cfa289`; response `caresp_0ca3823766edf3dc00biTZLQVBWJSTvfc8sy4PrBBEV9zGJyvB`; A2A task `TASK_STATE_COMPLETED`. The operator check is `installer/Install-JawsThroughStepC.ps1 -Mode Validate`. The functional test of the delegation is the same command with `-AcknowledgeInferenceCharges` (model usage, no Azure configuration writes). `-Mode Install -AcknowledgeStepCInstall` repairs one known gap per gate and is not required when Validate is already clean. Installer Pester 184 passed. [Closure commit](https://github.com/The-John-Charitable-Trust/Jaws/commit/401c7af751906a47c6d42cd0ffc1f473ad37f320); [merged PR #1](https://github.com/The-John-Charitable-Trust/Jaws/pull/1); runbook: [STEP-C-RUNBOOK.md](STEP-C-RUNBOOK.md).

**Do not** interpret Step C closure as proof of the end state. Azure MCP investigation, deliberation, remediation, the Datadog agent, and Teams are Steps D–I.
