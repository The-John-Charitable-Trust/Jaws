Developer / Tester Guide

This guide is for contributors and QA engineers who are validating JAWS source code and installer behavior. It covers Pester, .NET tests, Stage A installation-state discovery, and the Step C dev-project installer.

Scope: Install-Jaws.ps1 is Discover, Plan, and Package. A successful Stage A discovery is not a new cloud installation. Step C for the dev project is installer/Install-JawsThroughStepC.ps1. See the Step C runbook.

1. Developer and testing requirements

Required: Windows 10/11, Git, PowerShell 7, Azure CLI, Pester 5.x, .NET SDK compatible with the JAWS solution, Azure access for approved live discovery, and a code editor such as VS Code.

Pester is a tester/developer requirement only; ordinary JAWS customers do not need it. Stage A has no Azure provisioning mode. Step C install tests are source contracts and do not call Azure.

2. Clone the test branch

Open PowerShell 7 and clone the public or authorized repository:

Set-Location "$HOME\Documents"
git clone https://github.com/The-John-Charitable-Trust/Jaws.git
Set-Location .\Jaws
git status -sb
git log -1 --oneline

Use the reviewed commit for the test cycle. The repository is The-John-Charitable-Trust/Jaws. Step C validation is .\installer\Install-JawsThroughStepC.ps1 -Mode Validate.

3. Install and verify Pester 5

Open PowerShell 7, not the older Windows PowerShell console. Run the following commands to install Pester 5 side-by-side with Pester 3.4 if it exists:

# PowerShell 7: install Pester 5 for the current Windows user
Install-Module -Name Pester `
  -MinimumVersion 5.0.0 `
  -MaximumVersion 5.99 `
  -Scope CurrentUser `
  -Force `
  -SkipPublisherCheck

# Verify both installed and loaded modules
Get-Module -ListAvailable Pester | Select-Object Name,Version,Path
Import-Module Pester -MinimumVersion 5.0.0 -Force
Get-Module Pester | Select-Object Name,Version

Expected result: Get-Module Pester reports a version beginning with 5.. Pester 3.4 may remain installed.

If installation fails, verify access to the PowerShell Gallery and the current user's module installation permissions. Do not uninstall the built-in version solely for JAWS.

4. Run automated test suites

From the cloned repository root, run:

# From the Jaws repository root; use Pester 5
Import-Module Pester -MinimumVersion 5.0.0 -Force
Invoke-Pester .\tests\installer\ -Output Detailed

# Application regression tests (requires .NET SDK)
dotnet restore
dotnet build
# Run the current repository's test project(s) as documented.
# In the current JAWS source:
dotnet test .\tests\step-c\Jaws.Investigation.Tests.csproj
dotnet test .\tests\Jaws.Supervisor.Metadata.Tests\Jaws.Supervisor.Metadata.Tests.csproj
dotnet test .\tests\Jaws.FirstAgent.Tests\Jaws.FirstAgent.Tests.csproj

Expected: installer Pester, the Step C offline tests, the toolbox metadata probe, and the first-agent checks pass. Record actual counts. A successful parse is not a passed test run. If a test cannot execute, record it as BLOCKED. These commands do not call Azure.

5. Review JAWS state and scope

The current Stage A installer reads installer/config/jaws-installation-state.dev.json as the operator-managed authoritative JAWS resource inventory. It is designed for an existing development environment, not a new empty installation.

Use -StateFile and -EnvironmentName for a separate authorized tester configuration. Do not reuse the developer's Azure subscription or state file for tests in another tenant.

Record expected resource names and model version without including any secrets. Stage A does not write to the gold-copy state file.

Discover does not create this file and does not provision a tenant. The dev file is the gold copy for jaws-dev.
6. Execute Stage A discovery

After verifying the selected state file and authorization, execute only the installer:

.\installer\Install-Jaws.ps1 -Mode Discover -EnvironmentName dev

For an independent tester environment:

.\installer\Install-Jaws.ps1 -Mode Discover `
  -EnvironmentName tester `
  -StateFile ".\installer\config\jaws-installation-state.tester.json"

Expected: installer loads the state file, validates its subscription and resource group, scans all enabled subscriptions visible in the selected tenant, and compares recorded JAWS resources with Azure. No Azure writes.

7. Inspect scan and resource reports

The tenant-scan console report should show accessible subscriptions scanned, inaccessible subscriptions (if any), and JAWS-related matches. The resource comparison should show expected and observed resources with statuses, ownership and model-version drift where available.

Inspect the generated reports under installer/.local/. These files may contain sensitive environment metadata and must not be committed to a public repository.

Important: The tenant scan must not treat unrelated legacy resources as JAWS installations.

8. Repeat discovery and test reuse

Run the exact same installer invocation a second time. Confirm the persistent manifest contains no duplicate entries, preserves resource identity and ownership, and never rewrites the operator-managed gold-copy state in Discover mode.

Reinstallation in a new subscription and resource group requires a separate state file. Discover does not create that file. Repair of the existing dev project belongs to Install-JawsThroughStepC.ps1 -Mode Install, and only for the gates listed in the runbook.

9. Record acceptance and defects

Use the Manual Verification Guide to record expected and actual results, pass/fail/blocked status, relevant redacted evidence, reproduction instructions and issue severity.

The live close for the dev project, after the offline suites, is:

.\installer\Install-JawsThroughStepC.ps1 -Mode Validate
.\installer\Install-JawsThroughStepC.ps1 -Mode Validate -AcknowledgeInferenceCharges

The first command writes no Azure changes and should print VALIDATED. The second spends model usage, writes no configuration, and should print CLOSED with TASK_STATE_COMPLETED. Keep the gitignored receipts under installer\.local. Do not run -Mode Install unless Validate is BLOCKED on a repairable gate. See the Step C runbook.

JAWS documentation · Steps A–C are closed for the existing dev project. Discover still does not provision a new installation.
