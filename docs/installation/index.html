JAWS setup and installation

Install JAWS from GitHub

The JAWS GitHub repository is the distribution source for application code, the installer, configuration examples, tutorials, and verification guides. No developer-specific folder or separate installer overlay is required for published releases.

Release status: Stage A is a read-only discovery test, not a working first-time cloud deployment. First-time installation with automatic discovery and provisioning belongs to Stage B. These instructions assume the corresponding installer and guides have been committed to the GitHub repository being cloned.

Stage A guided test steps

Requirements

Windows 10/11, PowerShell 7, Azure CLI, Git, internet access, and an Azure identity with read access to the selected Azure environment. A code editor such as VS Code is optional.

The installer offers Microsoft Entra sign-in when the Azure CLI session is unavailable. A corporate administrator may need to grant access.

Stage A validates resource discovery only. It does not create resource groups, Foundry projects, deployments, identities, or secrets.
1. Clone JAWS from GitHub

JAWS is distributed through its GitHub repository. Cloning creates the local Jaws directory automatically, including the installer and its documentation. No ZIP extraction or manual merging is required.

  1. Install Git, PowerShell 7, and Azure CLI (see Requirements).
  2. Open PowerShell 7 from the Windows Start menu.
  3. Choose a parent folder, such as the current user's Documents folder.
  4. Run the following commands. The second command changes to the cloned repository directory.
Set-Location "$HOME\Documents"
git clone https://github.com/cezjah/Jaws.git
Set-Location .\Jaws

Already cloned? Open the existing clone instead, and follow the repository's documented upgrade process. Do not reclone over an existing directory.

Repository access: If GitHub reports that the repository cannot be found or access is denied, request access or wait until the repository becomes public. The installer must be committed to the release branch before these instructions work from a fresh clone.

Confirm that the new folder contains installer/Install-Jaws.ps1, docs/installation/index.html, and docs/verification/index.html. The public GitHub README should link directly to the two HTML guides.

2. Launch JAWS Setup
  1. With PowerShell open inside the Jaws folder, run Get-Location to confirm the current working directory.
  2. Run the Stage A installer command below. Do not run individual Azure CLI provisioning commands.
  3. Follow the prompts on screen.
Get-Location
.\installer\Install-Jaws.ps1 -Mode Discover
Stage A preview only: Discover reads Azure and writes local reports; it does not install Foundry or other resources. The full first-time installer will use -Mode Install after Stage B implementation and testing. Do not run -Mode Install against Stage A.

3. Authenticate with Microsoft Entra ID

If the installer detects an existing authenticated Azure CLI session, it proceeds. Otherwise, it asks permission to start Azure sign-in. Approve the prompt, complete the browser sign-in and any MFA, then return to PowerShell.

Do not capture passwords, API keys, security codes or access tokens in screenshots.

4. Choose an Azure subscription and resource group

The installer lists available enabled subscriptions by number. Select the subscription intended for the installation, then select its resource group by number. The selected scope belongs to the new user, not the JAWS developer.

If a subscription or resource group is not listed, verify account permissions. Stage A cannot create a new resource group; that capability is reserved for the full Install mode.

5. Review the tenant-wide inventory

Before the target inventory, JAWS scans all enabled subscriptions visible to the signed-in identity in the selected tenant. The installer displays a per-subscription console table, possible JAWS/Tight-Fang matches, and failed scans. It also saves a JSON report:

installer\.local\jaws-tenant-scan.dev.generated.json

A scan may find resources whose names or tags resemble JAWS. These are candidates, not confirmed installations. Failure to find a candidate does not prove that no JAWS installation exists.

If any visible subscription cannot be inventoried, Stage A reports the failure and does not replace the target manifest.

7. Review the resource manifest and console results

JAWS prints each discovered or missing resource, ownership, recommended action, and validation result to the PowerShell console. Model deployment entries also print the expected and observed model version when available.

The full JSON inventory is saved to:

installer\.local\jaws-resources.dev.generated.json

Resources existing before installation are initially classified as External, not installer-owned. The manifest may include Azure resource IDs; do not publish environment inventories in a public repository.

8. Repeat the Stage A run

Run the same installer command a second time, selecting the same Azure scope, environment and resource names:

.\installer\Install-Jaws.ps1 -Mode Discover

Expected behavior: no duplicate resource records, no Azure write operations, previous ownership preserved. This tests discovery repeatability. A full Install → Reinstall test becomes available after Stage B provisioning is developed.

Troubleshooting
ProblemAction
PowerShell cannot find the installerOpen PowerShell from the repository root, not the Downloads ZIP.
Azure CLI not foundInstall Azure CLI and restart PowerShell.
Azure sign-in failedRetry authentication or contact an Azure administrator.
Subscription/resource group not visibleCheck tenant, access rights, and PIM activation when applicable.
Tenant scan incompleteInspect console errors and the JSON scan report; do not assume missing permissions mean missing resources.
Manifest environment mismatchUse a unique -EnvironmentName for each installation target.

JAWS-only installation state (v0.4.5)

The tenant inventory displays JAWS and legacy Tight-Fang candidates separately. Only explicitly selected and verified JAWS resources are recorded in installer/.local/jaws-installation-state.<environment>.generated.json. Reinstallation loads that state and reuses its names. Legacy resources are never imported. Stage A is discovery-only; provisioning and overwrite require a future approved Install mode.
