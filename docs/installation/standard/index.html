Standard Installation Guide

This guide is for an administrator who wants to install and operate JAWS. It deliberately omits developer test frameworks and source-code testing instructions.

Closed through Step C on the dev project. Install-Jaws.ps1 0.4.10 supports greenfield Discover, Plan, Preflight, Package, and an approved Step B Install. Step B Install creates a new Foundry foundation and refuses the dev environment. The dev-project path remains installer/Install-JawsThroughStepC.ps1. See the Step C runbook.
First-time customer Step A: .\installer\Install-Jaws.ps1 -Mode Discover -NonInteractive -EnvironmentName your-environment -ResourceGroupName rg-jaws-your-environment -Location eastus prints STEP-A DISCOVERY PASS and Azure writes: 0. No state file is required. See the Step A walkthrough. The dev command -EnvironmentName dev remains the existing-project check.

1. System requirements

Production operators need a Windows workstation with internet access, Git, PowerShell 7, and Azure CLI, plus an Azure account authorized to install JAWS in the selected subscription.

Not required: Pester, .NET SDK, Visual Studio, or source-code testing tools. A Datadog Agent host is required only when Install configures Datadog. That host must already exist in the same subscription, the environment resource group, and the environment location. For the current test those are subscription c52f597b-7753-45b4-a764-67e290dcfd5e, resource group rg-aiops-lab-test2, and location eastus. A new environment that keeps the generated resource group uses rg-jaws-<environment>. The machine is Windows 11 or Windows Server 2016 or later, at least 2 vCPU, 8 GiB RAM, and 4 GiB free disk. Standard_D2s_v3 meets that minimum. The Datadog Agent must be installed, configured, and the datadogagent service must be Running. jaws-stepb-test in rg-jaws-stepb-test is the operator machine and is not this host. Skip Datadog when no agent host is part of this install. See System Prerequisites. To destroy one customer environment before a new install, see Uninstall.

Install-Jaws.ps1 0.4.10 implements Discover, Plan, Preflight, Package, Install, and Accept. Install creates a Step B foundation only after preflight, the plan digest, and -AcknowledgeStepBInstall. For the existing dev project, use .\installer\Install-JawsThroughStepC.ps1 -Mode Validate. For the environment Step B created, add -EnvironmentName.
2. Clone JAWS from GitHub
  1. Install Git, PowerShell 7 and Azure CLI if not already installed.
  2. Open PowerShell 7 using the Windows Start menu.
  3. Copy the commands below. A new Jaws folder will appear automatically.
Set-Location "$HOME\Documents"
git clone https://github.com/The-John-Charitable-Trust/Jaws.git
Set-Location .\Jaws

Open docs/installation/index.html inside the cloned repository to view the guide chooser. Stage A discovery is installer/Install-Jaws.ps1. The Step C dev-project installer is installer/Install-JawsThroughStepC.ps1.

3. Sign in

Open PowerShell 7 in the cloned repository and sign in to the dev subscription with Azure CLI. The installer uses that sign-in. It does not present a subscription picker or provision a new resource group.

az login
az account set --subscription "c52f597b-7753-45b4-a764-67e290dcfd5e"

The subscription above is the existing dev project. For a new foundation, select your own subscription with az account set and use the Step B commands. .\installer\Install-Jaws.ps1 -Mode Install creates nothing unless -AcknowledgeStepBInstall and the approved plan digest are both present. The dev-project command through Step C is .\installer\Install-JawsThroughStepC.ps1 -Mode Validate.

Step B · Install the foundation

Plan names the resources in the subscription selected by Azure CLI. Install creates the resource group, Foundry account and project, model deployment, Key Vault, registry, AcrPull for the project identity, and hosted Supervisor version 1 pinned to an image digest. Use your own environment name. An interactive Plan asks for it and offers resource group rg-jaws-<environment> and location eastus. dev and rg-aiops-lab are refused. Add -FoundryAccountName, -ProjectName, -KeyVaultName, -AcrName, or -SupervisorAgentName on Plan when you need a name other than the generated default. An omitted name stays the default, and the final names are locked by the plan digest. If Preflight finds the Foundry, Key Vault, or registry name taken, it says the name is not available and asks for another. An invalid answer is repeated. -NonInteractive stops and names the switch.

.\installer\Install-Jaws.ps1 -Mode Plan -NonInteractive -EnvironmentName your-environment -ResourceGroupName rg-jaws-your-environment -Location eastus

Expected: STEP-B PLAN PASS, Network profile: Public, Key Vault, Install authorized: false, and a Plan SHA-256. The digest does not by itself authorize creation or cost. A name that does not match the saved plan stops Preflight and Install at JAWS-STEP-B-016.

.\installer\Install-Jaws.ps1 -Mode Preflight -EnvironmentName your-environment -ResourceGroupName rg-jaws-your-environment -Location eastus

Expected: STEP-B PREFLIGHT PASS, Role assignment: true, Model quota: deferred, Policy simulation: not performed, and Azure writes: 0. JAWS-STEP-B-026 means fix the reported role or provider gap before Install.

.\installer\Install-Jaws.ps1 -Mode Install -EnvironmentName your-environment -ResourceGroupName rg-jaws-your-environment -Location eastus -ApprovedPlanSha256 <plan-sha> -AcknowledgeStepBInstall
.\installer\Test-JawsStepB.ps1 -Mode Install

Install builds the Supervisor image with az acr build --platform linux/amd64 and reads the digest from the registry. Docker Desktop is not required. -QuotaMode defaults to Static. Add -QuotaMode Dynamic to the same Install command when this deployment should use dynamic quota. The plan digest stays the same. Static keeps GlobalStandard capacity 1. Dynamic creates the regional Standard SKU at capacity 1, then sets dynamicThrottlingEnabled. Azure rejects that property on GlobalStandard. An existing GlobalStandard deployment is replaced by the Standard deployment. Dynamic quota can serve more than the capacity-1 rate when Azure has spare capacity, and those tokens are billed at the normal rate. The console prints Model SKU: GlobalStandard or Model SKU: Standard.

Expected: STEP-B INSTALL PASS, Quota mode: Static or Quota mode: Dynamic, Agent status: active, and an image ending in @sha256:. Test-JawsStepB.ps1 -Mode Install also prints Live Azure read: false. Receipt: installer/.local/jaws-step-b-install.your-environment.generated.json. These resources are billable.

Private profile

The commands above are the public profile. For a private account, plan with -NetworkProfile Private and install with that plan's digest. Run every command on this computer. There is no jump VM. The first Install creates the network and the private account, then pauses until the Azure VPN Client on this computer can reach services.ai.azure.com. Connect jaws-vpn-<compact>, set its DNS server to the printed resolver address, and run the same Install again. The gateway is VpnGw1AZ and bills for each hour it exists. The first Install waits while Azure provisions it, often 30 to 45 minutes. A refusal that public access is disabled pauses the same way as a DNS failure. Key Vault and the registry stay public. FedRAMP Moderate stays false. Install-JawsFoundryPrivateNetwork.ps1 is deprecated.

.\installer\Install-Jaws.ps1 -Mode Plan -NonInteractive -EnvironmentName your-environment -ResourceGroupName rg-jaws-your-environment -Location eastus -NetworkProfile Private
.\installer\Install-Jaws.ps1 -Mode Preflight -EnvironmentName your-environment -ResourceGroupName rg-jaws-your-environment -Location eastus
.\installer\Install-Jaws.ps1 -Mode Install -EnvironmentName your-environment -ResourceGroupName rg-jaws-your-environment -Location eastus -ApprovedPlanSha256 <plan-sha> -AcknowledgeStepBInstall

Expected first Install: STEP-B INSTALL PAUSED, Private posture: verified, and Supervisor created: false. The second Install prints STEP-B INSTALL PASS. A public digest stops at JAWS-STEP-B-011. An existing account that is not already private stops at JAWS-STEP-B-028. On 20 October 2026 the only JAWS resources left in subscription c52f597b-7753-45b4-a764-67e290dcfd5e are four soft-deleted Key Vault names. Azure will not purge them early. kv-jaws-lab-test2 and kv-jaws-dev-001 were deleted that evening with purge protection and stay reserved until 18 January 2027. kvjawsaiopslabtest2 and kvjawsaiopslabtest return DeletedVaultPurge, the same refusal recorded in October, and stay reserved until 18 January 2027 and 17 January 2027. Pass -KeyVaultName with a different name. kv-jaws-dev-001 is also reserved and stops at JAWS-STEP-B-017.

.\installer\Install-Jaws.ps1 -Mode Accept -EnvironmentName your-environment -ResourceGroupName rg-jaws-your-environment -Location eastus
.\installer\Test-JawsStepB.ps1 -Mode Accept

Expected: STEP-B ACCEPTANCE PASS, Live Azure read: true, Azure writes: 0, Foundry provisioning: Succeeded, Deployment: Succeeded, Registry admin: false, AcrPull: true, and Agent status: active. A receipt file alone throws JAWS-STEP-B-024. A fresh-subscription acceptance has not been recorded, so this step is not accepted yet.

5. Validate through Step C

This is the check that Steps A through C are in the approved shape on the dev project. It reads Azure and writes nothing.

.\installer\Install-JawsThroughStepC.ps1 -Mode Validate

A clean result prints VALIDATED. Acceptance is Skipped until the functional test below. The receipt is installer\.local\jaws-step-c-install.dev.generated.json.

The gates are prerequisites, the dev state file, the Investigation A2A card, prompt planner jaws-investigation-planner-dev, the RemoteA2A connection, toolbox jaws-investigation-a2a-tools default v2, one Foundry Agent Consumer role on the Supervisor instance, Supervisor v5 on the approved image, and the identity context. 6. Functional acceptance

This call spends model usage. It does not create, retarget, assign, or release anything. Run it only after Validate is VALIDATED.

.\installer\Install-JawsThroughStepC.ps1 -Mode Validate -AcknowledgeInferenceCharges

A pass prints CLOSED, with Acceptance Passed and TASK_STATE_COMPLETED in the tool output. A rate-limited response that already contains TOOL_INVOKED_SUCCEEDED and TASK_STATE_COMPLETED passes, and the report keeps the rate-limit error. A model rate limit with no completed Investigation task prints Issue and Action and, after three tries, stops at JAWS-C-ACCEPT-010. Re-run Step B Install with -QuotaMode Dynamic, or wait for the limit to reset and retry. That failure is not JAWS-C-ACCEPT-007. A completed response with only reasoning and a message is JAWS-C-ACCEPT-007: TOOL_NOT_INVOKED. An empty toolbox shell, with a default version and no version list, leaves the Supervisor with no tool to call. Step C Install creates the A2A version and reads it back before that gate can pass. A create response without the tool is JAWS-TOOLBOX-011. Re-run Install before Accept. Step C does not rebuild the image.

The acceptance report is installer\.local\jaws-step-c-final-acceptance.dev.generated.json. The response uses store=false, so keep that file. It cannot be read back from Foundry later.

Use -Mode Install -AcknowledgeStepCInstall only when Validate is BLOCKED on a gate the runbook says the installer may repair. Add -AcknowledgeInferenceCharges on that run when the repair and the model call should happen together.

7. What this release does not install

CLOSED means Supervisor v5 delegated a read-only plan to the prompt planner. Step D can record the catalog, one hosted specialist, and, outside the dev project, a browser toolbox on an internal-only Container Apps environment. Neither result means a new customer tenant was accepted, and neither proves Azure Policy or Defender evidence, Datadog, ServiceNow, remediation, or a live browser page load.

Steps E–I now have installers. Step E publishes the Supervisor to Teams and does not record a reply. Step F creates the observability prompt agent and does not attach Azure MCP. Step G records the Datadog and ServiceNow manifest and does not deploy the server. Step H records the virtual-machine grant and does not execute a change. Step I checks those receipts and prints Live incident: false. Secrets must never be printed or written into the state file. The commands are in the tutorial.

See the Step C runbook and the Manual Verification Guide.
