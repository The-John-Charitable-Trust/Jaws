Standard Installation Guide

This guide is for an administrator who wants to install and operate JAWS. It deliberately omits developer test frameworks and source-code testing instructions.

Closed through Step C on the dev project. Install-Jaws.ps1 is Discover, Plan, and Package. It does not provision a new Foundry account, and -Mode Install on that script is rejected. The operator path is installer/Install-JawsThroughStepC.ps1. See the Step C runbook.

1. System requirements

Production operators need a Windows workstation with internet access, Git, PowerShell 7, and Azure CLI, plus an Azure account authorized to install JAWS in the selected subscription.

Not required: Pester, .NET SDK, Visual Studio, or source-code testing tools.

Install-Jaws.ps1 implements Discover, Plan, and Package. It does not collect integration secrets or provision the cloud resources below. For the existing dev project, use .\installer\Install-JawsThroughStepC.ps1 -Mode Validate.
2. Clone JAWS from GitHub
  1. Install Git, PowerShell 7 and Azure CLI if not already installed.
  2. Open PowerShell 7 using the Windows Start menu.
  3. Copy the commands below. A new Jaws folder will appear automatically.
Set-Location "$HOME\Documents"
git clone https://github.com/The-John-Charitable-Trust/Jaws.git
Set-Location .\Jaws

Open docs/installation/index.html inside the cloned repository to view the guide chooser. Stage A discovery is installer/Install-Jaws.ps1. The Step C dev-project installer is installer/Install-JawsThroughStepC.ps1.

3. Sign in

Open PowerShell 7 in the cloned repository and sign in to the dev subscription with Azure CLI. The installer uses that sign-in. It does not present a subscription picker or provision a new resource group.

az login
az account set --subscription "c52f597b-7753-45b4-a764-67e290dcfd5e"

.\installer\Install-Jaws.ps1 -Mode Install is rejected. Discover, Plan, and Package remain on that script. The dev-project command through Step C is .\installer\Install-JawsThroughStepC.ps1 -Mode Validate.

4. Discover the dev project

Step A compares the gold-copy state file with Azure and writes a report under installer\.local. It does not change Azure or the state file.

.\installer\Install-Jaws.ps1 -Mode Discover -EnvironmentName dev

The authoritative file is installer/config/jaws-installation-state.dev.json for rg-aiops-lab and project jaws-dev. A missing or drifted identity stops the run. Unrelated Azure resources are not adopted.

5. Validate through Step C

This is the check that Steps A through C are in the approved shape on the dev project. It reads Azure and writes nothing.

.\installer\Install-JawsThroughStepC.ps1 -Mode Validate

A clean result prints VALIDATED. Acceptance is Skipped until the functional test below. The receipt is installer\.local\jaws-step-c-install.dev.generated.json.

The gates are prerequisites, the dev state file, the Investigation A2A card, prompt planner jaws-investigation-planner-dev, the RemoteA2A connection, toolbox jaws-investigation-a2a-tools default v2, one Foundry Agent Consumer role on the Supervisor instance, Supervisor v5 on the approved image, and the identity context. Supervisor v1 stays unchanged. Hosted jaws-investigation-dev is not the A2A target.

6. Functional acceptance

This call spends model usage. It does not create, retarget, assign, or release anything. Run it only after Validate is VALIDATED.

.\installer\Install-JawsThroughStepC.ps1 -Mode Validate -AcknowledgeInferenceCharges

A pass prints CLOSED, with Acceptance Passed and TASK_STATE_COMPLETED in the tool output. The acceptance report is installer\.local\jaws-step-c-final-acceptance.dev.generated.json. The response uses store=false, so keep that file. It cannot be read back from Foundry later.

Use -Mode Install -AcknowledgeStepCInstall only when Validate is BLOCKED on a gate the runbook says the installer may repair. Add -AcknowledgeInferenceCharges on that run when the repair and the model call should happen together.

7. What this release does not install

CLOSED means Supervisor v5 delegated a read-only plan to the prompt planner. It does not mean a new customer tenant was provisioned, and it does not prove hosted Investigation execution, Azure Policy or Defender evidence, Datadog, ServiceNow, or remediation.

Those remain later roadmap steps. Credential prompts for those integrations are not part of this installer. Secrets must never be printed or written into the state file.

See the Step C runbook and the Manual Verification Guide.
