Standard Installation Guide

This guide is for an administrator who wants to install and operate JAWS. It deliberately omits developer test frameworks and source-code testing instructions.

Current release boundary: Stage A v0.4.6 is a read-only discovery prototype. The steps for full first-time provisioning describe the approved Stage B user experience, not working functionality yet.

1. System requirements

Production operators need a Windows workstation with internet access, Git, PowerShell 7, and Azure CLI, plus an Azure account authorized to install JAWS in the selected subscription.

Not required: Pester, .NET SDK, Visual Studio, or source-code testing tools.

The current published Stage A installer implements only -Mode Discover. Cloud provisioning, key collection, integration configuration, and -Mode Install are not yet implemented. This guide describes the planned customer workflow but must not be used to claim a completed installation.
2. Clone JAWS from GitHub
  1. Install Git, PowerShell 7 and Azure CLI if not already installed.
  2. Open PowerShell 7 using the Windows Start menu.
  3. Copy the commands below. A new Jaws folder will appear automatically.
Set-Location "$HOME\Documents"
git clone https://github.com/cezjah/Jaws.git
Set-Location .\Jaws

Open docs/installation/index.html inside the cloned repository to view the guide chooser. The required installer file is installer/Install-Jaws.ps1.

3. Launch JAWS Setup

The planned first-time installation command is:

.\installer\Install-Jaws.ps1 -Mode Install
Not available in Stage A. Running the command above against the current v0.4.6 installer will fail because only Discover exists. To test the current read-only prototype, follow the Developer / Tester Guide.

4. Select the Azure installation environment

The installer will authenticate with Microsoft Entra ID, present accessible subscriptions, and ask which subscription and resource group should host JAWS. The chosen Azure scope belongs to the customer.

If the operator cannot access the selected subscription or lacks effective permissions to provision resources, setup must stop and explain what authorization is missing.

5. Review resources and installation plan

Setup will read an installation configuration and any prior JAWS state, scan accessible Azure subscriptions, and compare recorded resource identities with Azure. The operator will see which resources can be reused, which must be created, and which require an explicit decision.

A new customer starts without an installation-state file; the installer must generate it after verified provisioning. Existing customers reuse their state file. Discovery is built into Install, not a separate action for customers.

Only JAWS resources belong in the state. Unrelated application resources must never be adopted automatically.

6. Configure integrations securely

Optional integrations such as Datadog and ServiceNow will be configured through guided prompts. Where keys are needed, the installer must securely store them in Azure Key Vault or reference existing authorized secrets. Entra-managed identity is preferred when supported.

Secrets must never be printed to the console or included in the JSON state file.

Secure credential entry and integration configuration are future Stage B features; they are not part of the current Stage A script.
7. Verify installation and upgrade

Once Stage B is implemented, setup will verify resource health, model inference, required RBAC assignments, and connectivity. Reinstallation should read the existing JAWS state and skip matching healthy resources.

See the Manual Verification Guide for the present Stage A discovery tests and for later acceptance-test updates.
