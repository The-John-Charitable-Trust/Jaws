Standard Installation Guide

This guide is for an administrator who wants to install and operate JAWS. It deliberately omits developer test frameworks and source-code testing instructions.

Step A discovers. It does not install. Install-Jaws.ps1 -Mode Discover inventories the subscription you select through Azure Resource Graph and writes nothing. It does not load the development state file unless you pass -StateFile. -Mode Install is still rejected. Step C validation of the existing dev project remains installer/Install-JawsThroughStepC.ps1. See Step A and the Step C runbook.

1. System requirements

Production operators need a Windows workstation with internet access, Git, PowerShell 7, and Azure CLI, plus an Azure account authorized to install JAWS in the selected subscription.

Not required: Pester, .NET SDK, Visual Studio, or source-code testing tools.

Install-Jaws.ps1 implements Discover, Plan, and Package. Discover inventories the subscription and does not provision resources. Validate that report with .\installer\Test-JawsStepADiscovery.ps1. Step C validation of the existing dev project is a separate command, .\installer\Install-JawsThroughStepC.ps1 -Mode Validate.
2. Clone JAWS from GitHub
  1. Install Git, PowerShell 7 and Azure CLI if not already installed.
  2. Open PowerShell 7 using the Windows Start menu.
  3. Copy the commands below. A new Jaws folder will appear automatically.
Set-Location "$HOME\Documents"
git clone https://github.com/The-John-Charitable-Trust/Jaws.git
Set-Location .\Jaws

Open docs/installation/index.html inside the cloned repository to view the guide chooser. Stage A discovery is installer/Install-Jaws.ps1. The Step C dev-project installer is installer/Install-JawsThroughStepC.ps1.

3. Sign in

Open PowerShell 7 in the cloned repository and sign in. The installer lists the subscriptions this identity can see. It does not select the development subscription for you, and it does not create a resource group.

az login
az account list --query "[].{Name:name,SubscriptionId:id,State:state}" --output table

.\installer\Install-Jaws.ps1 -Mode Install is rejected. Discover, Plan, and Package remain on that script.

4. Discover your subscription

Step A queries Azure Resource Graph in the subscription you name. Foundry, Key Vault, and container registry rows are recorded as unclaimed. The command does not create resources and does not write an installation state file.

.\installer\Install-Jaws.ps1 -Mode Discover -SubscriptionId <your-subscription-id> -NonInteractive

Expected: Outcome NoInstallationState, AzureWrites 0, report installer\.local\jaws-step-a-discovery.selected.generated.json. Reader on that subscription must include Microsoft.ResourceGraph/resources/read. A denial returns JAWS-AUTH-010. Acceptance criteria are on the references page.

Reconcile the development project only when you intend to check that project:

.\installer\Install-Jaws.ps1 -Mode Discover -StateFile .\installer\config\jaws-installation-state.dev.json -NonInteractive

Expected: Outcome Reconciled when the named resources match. The state file is not rewritten. Do not point that file at a different subscription.

5. Validate Step A

Run this after Discover, in the same repository. It reads the local report. It does not call Azure.

.\installer\Test-JawsStepADiscovery.ps1 -ReportPath .\installer\.local\jaws-step-a-discovery.selected.generated.json

Expected: STEP-A PASS, Outcome NoInstallationState, and Azure writes: 0. The check fails unless AzureWrites is 0, InstallationStateCreated is false, and every inventory row is Unclaimed.

  • JAWS-STEP-A-001 means the report is missing. That is not a pass. Run Discover first.
  • JAWS-STEP-A-002 means Outcome Drift. The state file was not rewritten, and the named resources did not match.
  • JAWS-STEP-A-003 means a write, an adopted row, or an outcome that does not meet the criteria.

For the development state file, point -ReportPath at installer\.local\jaws-step-a-discovery.dev.generated.json. STEP-A PASS then requires Outcome Reconciled. The same checks are on the manual verification page. A Discover command that has not been run against Azure is BLOCKED, not passed.

6. Validate the dev project through Step C

This is the check that Steps A through C are in the approved shape on the dev project. It reads Azure and writes nothing.

.\installer\Install-JawsThroughStepC.ps1 -Mode Validate

A clean result prints VALIDATED. Acceptance is Skipped until the functional test below. The receipt is installer\.local\jaws-step-c-install.dev.generated.json.

The gates are prerequisites, the dev state file, the Investigation A2A card, prompt planner jaws-investigation-planner-dev, the RemoteA2A connection, toolbox jaws-investigation-a2a-tools default v2, one Foundry Agent Consumer role on the Supervisor instance, Supervisor v5 on the approved image, and the identity context. Supervisor v1 stays unchanged. Hosted jaws-investigation-dev is not the A2A target.

7. Functional acceptance

This call spends model usage. It does not create, retarget, assign, or release anything. Run it only after Validate is VALIDATED.

.\installer\Install-JawsThroughStepC.ps1 -Mode Validate -AcknowledgeInferenceCharges

A pass prints CLOSED, with Acceptance Passed and TASK_STATE_COMPLETED in the tool output. The acceptance report is installer\.local\jaws-step-c-final-acceptance.dev.generated.json. The response uses store=false, so keep that file. It cannot be read back from Foundry later.

Use -Mode Install -AcknowledgeStepCInstall only when Validate is BLOCKED on a gate the runbook says the installer may repair. Add -AcknowledgeInferenceCharges on that run when the repair and the model call should happen together.

8. What this release does not install

CLOSED means Supervisor v5 delegated a read-only plan to the prompt planner. It does not mean a new customer tenant was provisioned, and it does not prove hosted Investigation execution, Azure Policy or Defender evidence, Datadog, ServiceNow, or remediation.

Those remain later roadmap steps. Credential prompts for those integrations are not part of this installer. Secrets must never be printed or written into the state file.

See the Step C runbook and the Manual Verification Guide.
