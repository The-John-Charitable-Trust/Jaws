Before you begin

Windows, PowerShell 7, Git, Azure CLI, access to the approved JAWS DEV subscription, and a signed-in Azure CLI session. The existing Step C installer does not provision a brand-new environment. Use the detailed runbook if validation is blocked.

git clone https://github.com/The-John-Charitable-Trust/Jaws.git
cd Jaws
az login
# Select the authorized JAWS DEV subscription:
az account set --subscription <subscription-id>

If JAWS is already cloned, work from the approved installation branch and pull the latest changes rather than cloning again.

Available steps

Step A: Discover and verify state
.\installer\Install-Jaws.ps1 -Mode Discover -EnvironmentName dev

Expected: Reports reconcile authoritative DEV state and Azure; no Azure writes. Evidence: installer/.local/. Acceptance details.

Step B: Validate existing Foundry foundation

Step B was implemented for this DEV project, but its full first-time install is not a supported one-command Quick Start. Use the consolidated read-only through-Step-C validator below; it checks existing foundation dependencies without creating new resources. See Standard Guide.

Step C: Validate approved Supervisor → Investigation Planner integration
.\installer\Install-JawsThroughStepC.ps1 -Mode Validate

Expected: VALIDATED, no Azure configuration writes. Report: installer/.local/jaws-step-c-install.dev.generated.json.

Optional billable functional test:

.\installer\Install-JawsThroughStepC.ps1 -Mode Validate -AcknowledgeInferenceCharges

Expected: CLOSED, acceptance passed, TASK_STATE_COMPLETED. Report: installer/.local/jaws-step-c-final-acceptance.dev.generated.json.

Only if blocked on a documented, repairable gate:

.\installer\Install-JawsThroughStepC.ps1 -Mode Install -AcknowledgeStepCInstall

This may change Azure configuration. Review the repair gate list and obtain the necessary authorization first. It is not part of routine validation.

Steps D–I: not yet installable

Step D (VM specialist and compute), E (Azure MCP investigation), F (deliberation/remediation), G (observability specialist), H (Teams projects), and I (end-to-end acceptance) are planned. Their installation and validation commands will appear here only after their code and tests are accepted. See Microsoft sources and acceptance criteria for their targets.

What success means

Current acceptance proves a DEV-hosted Supervisor can delegate to the A2A prompt planner and return a read-only plan. It does not prove hosted Investigation runtime execution, Azure MCP queries, remedial writes, Teams integration or production readiness.
