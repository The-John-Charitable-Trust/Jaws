Before you begin: required software and access

This Quick Start uses the JAWS system prerequisites specification. Operator mode validates existing DEV resources; Developer / Tester mode additionally builds containerized .NET agents and runs regression tests. Greenfield Foundry provisioning is not yet available in this Quick Start.

Hardware and operating system

  • Windows 11 workstation with hardware virtualization enabled. Development workstation recommendation: 32 GB RAM / 1 TB SSD, especially for Docker Desktop, WSL 2 and .NET builds. The repository does not establish an absolute minimum RAM/disk requirement.
  • Internet access to GitHub, Microsoft package downloads, Azure management endpoints, Microsoft Foundry and the authorized container registry.

Install Pester for developer / tester validation

Install-Module -Name Pester -MinimumVersion 5.0.0 -MaximumVersion 5.99 -Scope CurrentUser -Force -SkipPublisherCheck
Import-Module Pester -MinimumVersion 5.0.0 -Force
Get-Module Pester | Select-Object Name,Version

Run in PowerShell 7; follow organizational package trust and execution policies. If package repository prompts appear, verify the publisher before proceeding.

Permission and execution-policy checks

  • Sign in with an authorized Microsoft Entra identity. Verify permission on the target subscription, JAWS resource group, Foundry project, registry, and role assignment operations only when explicitly approved. Read-only validation never implies permission to provision or modify resources.
  • Review Get-ExecutionPolicy -List before running downloaded PowerShell scripts. Respect MachinePolicy/UserPolicy and avoid permanent execution-policy bypasses. See Microsoft execution-policy guidance.
  • Docker must use Linux containers; image builds targeting hosted agents must use linux/amd64. Do not activate Docker merely for read-only Step A.

Clone the approved source and authenticate

git clone --branch feature/step-c-investigation-publishing https://github.com/The-John-Charitable-Trust/Jaws.git
cd Jaws
az login
az account set --subscription <approved-dev-subscription-id>
az account show --query "{name:name,id:id,tenantId:tenantId}" --output table
Get-ExecutionPolicy -List

If the repository is already cloned, review uncommitted changes before switching to the approved branch and pulling; do not overwrite local work.

Full build / container preflight (developer / tester)

pwsh -NoProfile -File .\installer\Test-JawsPrerequisites.ps1 -RequireContainerBuild
Invoke-Pester .\tests\installer\ -Output Detailed
dotnet run --project tests/Jaws.FirstAgent.Tests

Expected: prerequisite checks succeed, Pester and .NET tests pass, and Docker reports Linux. These are developer/tester validation commands; do not interpret them as cloud deployment or Step C live acceptance. Consult the Developer/Tester Guide and full prerequisite specification for environment-specific troubleshooting.

Available steps

Step A: Discover and verify state
.\installer\Install-Jaws.ps1 -Mode Discover -EnvironmentName dev

Expected: Reports reconcile authoritative DEV state and Azure; no Azure writes. Evidence: installer/.local/. Acceptance details.

Step B: Validate existing Foundry foundation

Step B was implemented for this DEV project, but its full first-time install is not a supported one-command Quick Start. Use the consolidated read-only through-Step-C validator below; it checks existing foundation dependencies without creating new resources. See Standard Guide.

Step C: Validate approved Supervisor → Investigation Planner integration
.\installer\Install-JawsThroughStepC.ps1 -Mode Validate

Expected: VALIDATED, no Azure configuration writes. Report: installer/.local/jaws-step-c-install.dev.generated.json.

Optional billable functional test:

.\installer\Install-JawsThroughStepC.ps1 -Mode Validate -AcknowledgeInferenceCharges

Expected: CLOSED, acceptance passed, TASK_STATE_COMPLETED. Report: installer/.local/jaws-step-c-final-acceptance.dev.generated.json.

Only if blocked on a documented, repairable gate:

.\installer\Install-JawsThroughStepC.ps1 -Mode Install -AcknowledgeStepCInstall

This may change Azure configuration. Review the repair gate list and obtain the necessary authorization first. It is not part of routine validation.

Steps D–I: not yet installable

Step D (VM specialist and compute), E (Azure MCP investigation), F (deliberation/remediation), G (observability specialist), H (Teams projects), and I (end-to-end acceptance) are planned. Their installation and validation commands will appear here only after their code and tests are accepted. See Microsoft sources and acceptance criteria for their targets.

What success means

Current acceptance proves a DEV-hosted Supervisor can delegate to the A2A prompt planner and return a read-only plan. It does not prove hosted Investigation runtime execution, Azure MCP queries, remedial writes, Teams integration or production readiness.
